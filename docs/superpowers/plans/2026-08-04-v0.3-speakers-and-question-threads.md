# LocoWiki V0.3 Speakers and Question Threads Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Extend the S24 Ultra V0.2.1 app with local SELF voiceprint enrollment, SELF/OTHER recognition, optional A/B/C/D clustering, question-to-self detection, deterministic continuous question threads, manual correction, and post-meeting global reclustering without changing the existing ASR and fact-query path.

**Architecture:** Add an isolated speaker subsystem driven by Sherpa speaker embeddings. It receives finalized VAD segments asynchronously, persists embeddings and speaker decisions in Room, and annotates existing utterances. A rule-based target classifier and thread assembler consume annotated utterances; failures degrade to UNKNOWN and never block ASR, meeting recording, or structured fact lookup.

**Tech Stack:** Kotlin, Jetpack Compose, Coroutines/StateFlow, Sherpa-ONNX 1.13.2, 3D-Speaker CAMPPlus 16 kHz model, Room 3, Bundled SQLite, JUnit 4.

## Global Constraints

- Target device: Samsung Galaxy S24 Ultra, arm64-v8a.
- No `android.permission.INTERNET` in the APK.
- Existing Sherpa ASR, VAD, Room/FTS5, meeting archive, and query latency path remain available when speaker features fail.
- SELF registration needs three accepted speech segments and stores embeddings only.
- Other-speaker clustering is optional; SELF verification remains enabled when a profile exists.
- No vector semantic retrieval in V0.3; that remains V0.4.
- Build as application ID `com.qujindai.locowiki.flashrecall.v03`, version `0.3.0`, side-by-side with V0.2.1.
